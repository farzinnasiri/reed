Other numbers

  • Press-in: scale .97 (chips, buttons) or .92 (mascot), 90 ms timing; release with snappy (buttons) or pop (mascot, composer).
  • Composer pop: withSequence(withTiming(1.03, {duration: 110}), withSpring(1, pop)).
  • Reveal: per sentence 180 ms fade + 4 px rise, 90 ms stagger. Cards: 12 px rise, scale .96, smooth.
  • Rubber band: d = (1 − 1 / (x · 0.55 / H + 1)) · H, H = list height. Threshold 64 pt on screen.
  • Hints (“Thinking”) appear after 400 ms, never sooner. “Still thinking” at 8 s.
  • Whisper: lives 6 s; ≤ 80 characters; one per exercise + PR + caution.
  • Idle: glance every 20–40 s after 45 s idle; sleepy after 3 min.
  • Glow props: energy · cy · spread · warmth · breath · speed + wave(); smoothing τ 350 ms; breath ±32 % over 2.4 s.

Backend (Convex) needs

  • Chapters. Assign chapterId when a message is written: new chapter if the gap to the previous message > chapterGapMinutes (server config, default 60) or a workout session started/ended in between. Chapter doc: startedAt (UTC), sessionId?, closedAt?. Backfill existing threads. Queries: current chapter messages (paginated, newest 30), previous chapter by cursor, chapter label data. getPresence adds currentChapterId and whether a new chapter would start now (now arg, as with other time-based queries).
  • Message context. Optional context: { sessionId, exerciseId?, setIndex? } on user messages; included in Reed’s prompt context; validated against the user’s live session.
  • Session whisper. reed.getSessionWhisper({ sessionId, exerciseId, now }) → null | { kind: 'info' | 'pr' | 'caution', text }. Deterministic from existing session data; no LLM in v1. Rate rules enforced server-side (one per exercise + pr + caution).
  • No cancel/stop for replies, no streaming: the design works without them. If streaming comes later, keep the per-sentence reveal.

Performance budget

  • 60 fps on a mid-range Android (the owner’s device class) for every step. No animation on the JS thread.
  • Glow: ≤ 2 ms per frame on the UI thread; render at 30 fps while resting (skip frames), 60 fps during reactions (wave, focus).
  • Ambient loops (glow, breathing, idle glances) pause when home is not focused, the app is not active, Low Power Mode is on, or Reduce Motion is on.
  • No new re-renders per keystroke beyond today’s; word-boundary reactions only touch shared values.
  • Thread: only the current chapter is rendered on open (typically < 30 rows).

Build order

  1. Presence hook + mascot API (gaze, react) with no visual change yet. Pages 01, 06.
  2. Composer: pop, rim, button collapse, mic ↔ send, growth, waiting Send. Page 02.
  3. Send and receive: lift overlay, make-room, sentence reveal, widget enter, hint timing, filler rows removed. Pages 01, 03.
  4. Chapters (backend first), chapter-only thread, pull-to-load, “Earlier”, “Latest”, today mode from the chapter rule. Page 04.
  5. Suggestions rules. Page 05.
  6. Glow field (Skia), states, wave, tilt, pause rules. Page 01.
  7. Touching Reed: tap to talk and eyes first; easter eggs last. Page 06.
  8. Session, proactive: header mascot, set nod, whispers (backend whisper query). Page 07.
  9. Session, on call: Reed sheet, context, session chips, swap roll, voice. Page 08.
  10. Reduce Motion, pause rules, device QA on Android and iOS for every step of every page.

How to check the work

  • For every step on every page: a screen recording from a real Android device next to the mockup at ½× and 1×. Timings within ±15 %, order identical, nothing extra moving.
  • Toggle Reduce Motion on the device and repeat; every step must match its Reduce Motion line.
  • Interrupt everything: tap during the glide, pull during a reveal, send during a pull. Nothing jumps; springs retarget.
  • Leave home and come back mid-animation: no stuck states, ambient loops resume.
